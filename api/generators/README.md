# Generator configuration

One config per language, used by [`hack/generate-sdks.sh`](../../hack/generate-sdks.sh).
They are here rather than beside the output because they describe how to
*generate* an SDK, and the output directory is what a consumer reads.

| File | Language |
|---|---|
| `python.yaml` | Python |
| `typescript.yaml` | TypeScript |
| `java.yaml` | Java |
| `<lang>.openapi-generator-ignore` | what not to generate, per language |

Go has no config here. It is generated by oapi-codegen rather than
openapi-generator, configured in [`sdk/go/oapi-codegen.yaml`](../../sdk/go/oapi-codegen.yaml)
next to the code it produces, and wired through `go:generate`.

## Why these settings

The choices are the same idea in four places: **the smallest dependency for the
consumer, and no release scaffolding for a package that is not released.**

- **`python.yaml`** uses `library: urllib3`. The generator's default is
  `asyncio`, which forces every caller into an async program; `urllib3` is
  synchronous, and a script that creates a sandbox does not want to be a
  coroutine to do it.
- **`typescript.yaml`** uses `typescript-fetch` rather than `typescript-axios`,
  so the package has no runtime dependency at all — `fetch` is in every browser
  and every current Node. The console is a single HTML file with no build step,
  and the SDK describing it should be equally dependency-free.
- **`java.yaml`** uses `library: native` rather than `okhttp-gson`. `native`
  means `java.net.http`, which is in the JDK, so the only dependencies are the
  Jackson jars the generated `pom.xml` names. The project's own container is
  distroless and has no Java at all — this SDK is for someone else's program.
- **`dateLibrary: java8`** and **`java8: false`** in `java.yaml`: Java 11 is the
  oldest LTS still receiving updates, and it produces cleaner code than the
  generator's Java 8 default.

## The ignore files

openapi-generator emits a full release project for every language: a publishing
script, CI config for three hosts, a test suite for an API it never calls,
and — for Java — a build file for every build system it supports.

None of that belongs here. The generated code is committed, consumed from the
repository, and released (if at all) by this repository's own process.

The ignore file has to be *inside the output directory* for the generator to
read it, which is a problem: the first thing anyone does when the output looks
wrong is delete the directory, and that would take the ignore file with it and
quietly regenerate everything it was suppressing. So it lives here, beside the
config, and `hack/generate-sdks.sh` copies it in before each run.

`java.openapi-generator-ignore` also drops `api/` — the Java generator writes a
second copy of the spec next to the code it generated, and a second copy of the
source of truth is one that can disagree with the first.

## Changing a generator

The version is pinned in `hack/generate-sdks.sh` (`OPENAPI_GENERATOR_VERSION`).
It is pinned rather than "latest" because the generated code is committed: a
moving version would show up as a large diff nobody asked for and nobody can
review. Bumping it is a deliberate act with its own commit, and the diff it
produces is the review.
