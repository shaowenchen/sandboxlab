# sandboxlab SDKs

Client libraries for a sandboxlab control plane, generated from one document.

| Language | Directory | Generated by | Runtime dependencies |
|---|---|---|---|
| Go | [`go/`](go/) | [oapi-codegen](https://github.com/oapi-codegen/oapi-codegen) | `oapi-codegen/runtime`, `google/uuid` |
| Python | [`python/`](python/) | openapi-generator | `urllib3`, `python-dateutil`, `pydantic` |
| TypeScript | [`typescript/`](typescript/) | openapi-generator | none (uses `fetch`) |
| Java | [`java/`](java/) | openapi-generator | Jackson |

Every one of them is generated from [`api/openapi.yaml`](../api/openapi.yaml),
which is the source of truth for this API. The server's routes, the web console
and the `sandbox` CLI are all described by that document too, so the SDKs and the
service cannot describe different APIs.

## Generating

```sh
make sdk             # regenerate all four from the spec
make sdk-check-go    # regenerate and fail if the committed Go SDK disagrees (no JRE)
make sdk-check       # the same for all four; needs a JRE for the generator
```

The output is committed. A Python user should be able to install the package
without a Java toolchain, and a Go user should be able to `go get` without a code
generator — that is the point of publishing generated code.

[`hack/generate-sdks.sh`](../hack/generate-sdks.sh) does the work. It pins the
openapi-generator version, downloads the jar into `.cache/` on first use, and
generates every language from the one spec. `.github/workflows/sdk.yml`
regenerates on every push to `main` and commits the result when it differs; on a
pull request it regenerates and checks the output compiles without committing
anything.

Editing the generated code is not how you change an SDK. Edit the spec.

## Hand-written versus generated

In each directory, files are either generated or written by hand, and only the
hand-written ones are edited:

| Directory | Generated | Hand-written |
|---|---|---|
| `go/` | `client.gen.go` | `domain.go`, `client.go`, `doc.go`, `*_test.go` |
| `python/` | `sandboxlab/` | nothing |
| `typescript/` | `src/` | nothing |
| `java/` | `src/main/java/` | nothing |

The Go SDK is the exception because Go does not allow a method to be defined on
a type from another package: `Template.Validate`, `Sandbox.TTLRemaining` and the
catalog type have to live in the same package as the types they extend, so they
are separate files from the generated ones and survive regeneration.

## Connecting

A control plane takes its key in one of two headers, and the data plane also
accepts it as a query parameter — a browser navigation cannot set a header.

```
X-Sandbox-Key: <key>
Authorization: Bearer <key>
```

There is one key, held by the deployment, and it may do everything. A request
either presents it or it does not.

### Go

```go
client, err := sdk.New(sdk.Options{
    BaseURL: "https://sandboxlab.example.com/sandbox",
    Key:     os.Getenv("SANDBOXLAB_KEY"),
})
if err != nil {
    return err
}

created, err := client.CreateSandboxWithResponse(ctx, sdk.CreateSandboxRequest{
    Template: "agent-infra",
    Name:     "myshop",
    TTL:      "30m",
})
if err != nil {
    return err
}
if err := sdk.Check(created.HTTPResponse, created.Body); err != nil {
    return err
}
fmt.Println(created.JSON201.ID)
```

### Python

```python
from sandboxlab import ApiClient, Configuration
from sandboxlab.api import SandboxesApi
from sandboxlab.models import CreateSandboxRequest

config = Configuration(host="https://sandboxlab.example.com/sandbox")
config.api_key["ApiKey"] = os.environ["SANDBOXLAB_KEY"]
api = SandboxesApi(ApiClient(configuration=config))

sandbox = api.create_sandbox(CreateSandboxRequest(
    template="agent-infra", name="myshop", ttl="30m",
))
print(sandbox.id, sandbox.state)
```

### TypeScript

```ts
import { Configuration, SandboxesApi } from "sandboxlab";

const withKey = {
  pre: async (ctx) => {
    ctx.init.headers = { ...ctx.init.headers, "X-Sandbox-Key": key };
    return ctx;
  },
};
const api = new SandboxesApi(new Configuration({
  basePath: "https://sandboxlab.example.com/sandbox",
  middleware: [withKey],
}));

const sandbox = await api.createSandbox({
  createSandboxRequest: { template: "agent-infra", name: "myshop", ttl: "30m" },
});
console.log(sandbox.id, sandbox.state);
```

### Java

```java
ApiClient client = new ApiClient();
client.setScheme("https");
client.setHost("sandboxlab.example.com");
client.setBasePath("/sandbox");
client.setRequestInterceptor(b -> b.header("X-Sandbox-Key", key));

SandboxesApi api = new SandboxesApi(client);
CreateSandboxRequest req = new CreateSandboxRequest();
req.setTemplate("agent-infra");
req.setName("myshop");
req.setTtl("30m");
Sandbox sandbox = api.createSandbox(req);
System.out.println(sandbox.getId() + " " + sandbox.getState());
```

The Java client builds its address from scheme, host, port and base path
separately rather than from a URL — `setBasePath` is a path prefix, not an
origin.

## A note on durations and keys

Durations cross the wire as strings — `"30m"`, `"2h"`, `"90s"` — in a create or
renew request. A response reports a lifetime as the RFC 3339 timestamp it ends
at, in `expiresAt`, rather than as a count: the time is what the cluster records
and what a client needs, so nothing has to agree on a unit.

`expiresAt` is absent rather than zero when it does not apply. "No expiry" is
the absence of `expiresAt`, not a time in the year 1 — check for the field, not
for a value. The Go SDK adds `Sandbox.TTLRemaining` and `Sandbox.Expired` on top
of the generated type to turn the timestamp into "how long is left"; the wire
itself carries no duration.

## Testing an SDK against a real deployment

The Go SDK's tests run against an `httptest` server and cover the client's own
behaviour. To check a generated client against a live control plane, point it at
a running deployment:

```sh
export SANDBOXLAB_KEY=...
go run ./cmd/sandbox --url https://sandboxlab.example.com/sandbox list
```

and then assert what you actually care about. The four SDKs are generated from
one document, so a client that speaks the API correctly is evidence about all
four — the wire shapes are not four different things.
